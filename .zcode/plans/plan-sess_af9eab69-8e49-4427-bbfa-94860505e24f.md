## 一、权限设计（重点）

### 1.1 角色层级（4 级 RBAC）

| 角色 | code | 定位 | 谁能分配 |
|------|------|------|----------|
| **超级管理员** | `SUPER_ADMIN` | 你。拥有一切权限，系统至少保留 1 个，不可被删除/降级 | 仅系统初始化 |
| **管理员** | `ADMIN` | 日常管理者。管理用户和内容，但不能改其他管理员和系统配置 | 仅 SUPER_ADMIN |
| **经理** | `MANAGER` | 业务执行者。查看数据、操作业务，不能管理用户 | SUPER_ADMIN / ADMIN |
| **员工** | `STAFF` | 普通成员。只能查看和操作自己的数据 | SUPER_ADMIN / ADMIN |

### 1.2 权限矩阵（代码里定义，不建权限表——原型阶段 YAGNI）

| 操作 | SUPER_ADMIN | ADMIN | MANAGER | STAFF |
|------|:---:|:---:|:---:|:---:|
| 查看用户列表 | ✓ | ✓ | ✓ | ✗ |
| 创建用户 | ✓ | ✓ | ✗ | ✗ |
| 编辑用户资料 | ✓ | ✓ | ✗ | ✗ |
| 修改用户角色 | ✓ | ✗ | ✗ | ✗ |
| 删除用户 | ✓ | ✗ | ✗ | ✗ |
| 停用/启用用户 | ✓ | ✓ | ✗ | ✗ |
| 表单管理 | ✓ | ✓ | ✓ | ✓(自己的) |
| 系统配置 | ✓ | ✗ | ✗ | ✗ |

### 1.3 层级安全规则（后端守卫强制校验，前端只是体验）
1. **SUPER_ADMIN 不可被删除**，且系统至少保留 1 个（删除/降级前检查）
2. **低层级不能操作高层级**：ADMIN 不能改/删 SUPER_ADMIN；MANAGER/STAFF 不能操作任何人
3. **只有 SUPER_ADMIN 能分配 ADMIN 及以上角色**
4. **停用的用户（status=DISABLED）登录被拒**，即使密码正确

## 二、数据模型（packages/database/prisma/schema.prisma）

```prisma
model User {
  id           String     @id @default(cuid())
  email        String     @unique
  name         String
  passwordHash String
  role         Role       @default(STAFF)
  status       UserStatus @default(ACTIVE)
  avatarUrl    String?
  lastLoginAt  DateTime?
  createdAt    DateTime   @default(now())
  updatedAt    DateTime   @updatedAt
}

enum Role {
  SUPER_ADMIN
  ADMIN
  MANAGER
  STAFF
}

enum UserStatus {
  ACTIVE      // 正常
  DISABLED    // 已停用
}
```

> 简化版 RBAC：角色用枚举字段（单角色），权限矩阵在代码里定义。未来要细粒度权限（多角色+权限点）再加 Role/Permission/RolePermission 三张表，当前模型不影响后续扩展。

## 四、API 端点

### 认证 (`/auth`)
| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/auth/login` | 无 | 邮箱+密码登录，返回 accessToken + refreshToken |
| POST | `/auth/refresh` | refreshToken | 刷新 accessToken |
| GET | `/auth/me` | JWT | 当前用户信息 |
| POST | `/auth/logout` | JWT | 登出（拉黑 refreshToken） |

### 用户 (`/users`)
| 方法 | 路径 | 需要角色 | 说明 |
|------|------|----------|------|
| GET | `/users` | ADMIN+ | 用户列表（分页/搜索/筛选） |
| POST | `/users` | ADMIN+ | 创建用户 |
| PATCH | `/users/:id` | ADMIN+ | 编辑用户（层级校验） |
| PATCH | `/users/:id/role` | **SUPER_ADMIN** | 修改角色 |
| PATCH | `/users/:id/status` | ADMIN+ | 停用/启用 |
| DELETE | `/users/:id` | **SUPER_ADMIN** | 删除（保留至少 1 个超管） |

## 六、启动流程

```bash
# 1. 装依赖
pnpm install

# 2. 起 PostgreSQL（Docker）
pnpm docker:up        # → localhost:5432, 用户 hgbord / 库 hgbord

# 3. 配置环境变量
cp .env.example .env  # 各 app 也需要 cp apps/*/.env.example

# 4. 建表 + 创建你的账号
pnpm db:migrate
pnpm db:seed           # → 打印你的账号信息

# 5. 启动开发服务器
pnpm dev
#   admin → http://localhost:3000
#   api   → http://localhost:4000
```

打开 http://localhost:3000/login → 用你的账号登录 → 进入用户管理。
